# V0.8 模块细节与生命周期

## 设计原则

每个模块必须同时回答五个问题：

1. 当前状态是什么；
2. 用户下一步可以做什么；
3. 动作是否可撤销；
4. 变化如何进入CHART Context；
5. 谁在何时改变了什么，能否追溯。

因此V0.8不以“增加页面”为目标，而是将所有核心对象补齐为可逆状态机。

## 目标

状态：`active / paused / completed / archived`。

编辑包含标题、背景、成果、层级和日期。目标名称与会话标题事务同步；归档目标不会删除任何资产。

## 路径与里程碑

路径版本不可覆盖。重编译会归档旧路径并生成新版本。里程碑按顺序解锁，完成记录时间与证据要求。

## 任务

状态：`todo / doing / blocked / done / archived`。

完成时写入`completed_at`；重开时清除完成时间；归档不删除任务。恢复后回到明确的可执行状态。

## 复习

复习项目既可以按间隔算法推进，也可以暂停。暂停项目不进入到期队列；恢复后保持既有记忆参数。

## 误解

状态：`open / testing / resolved / recurring`。

解决时写入`resolved_at`；复发时清除解决时间并保留历史复发计数。

## 资料

归档资料保留分块与来源，但从检索候选集中排除。恢复后无需重新导入或重新分块。

## 评估

归档不会删除题目和答题历史。恢复状态依据是否存在尝试自动选择：

- 无尝试：`ready`；
- 有尝试：`completed`。

## 作品

作品恢复依据最近验收：

- 无验收：`draft`；
- 验收未通过：`review`；
- 验收通过：`accepted`。

## 证据

证据默认不可随意删除。它用于能力判断、迁移验证和后续复盘，需保留来源关系。

## 运行

Agent Run具备暂停、恢复、取消、审批、Checkpoint、成本和Trace。运行只关联当前目标与会话。

## 本地维护

维护快照包含：

- Schema版本；
- 数据库字节数；
- 完整性状态；
- 备份数量与时间；
- 各核心表记录数。

备份恢复必须经过路径白名单、SQLite完整性检查、恢复前保护性备份和应用重启后的原子替换。
