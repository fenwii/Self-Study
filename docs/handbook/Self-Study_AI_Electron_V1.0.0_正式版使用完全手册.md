# 第一篇：认识 Self-Study AI

## 1. 产品定位

Self-Study AI 是一个本地优先、目标隔离、长期可恢复、可审计的 Electron 原生一对一自学操作系统。

它不是单纯的聊天机器人，也不是课程列表、打卡工具或答案生成器。系统的正式成功标准是：

> 学习者能否在更少 AI 提示下理解知识、延迟保持、跨场景迁移，并独立完成可验收的真实作品。

完整学习链为：

```text
真实目标
→ 一对一学习契约
→ 行为条件诊断
→ 锚点与最小行动
→ 个性化学习路径
→ 主动练习与误解修复
→ 间隔复习
→ 真实性评估
→ 作品验收
→ 能力证据
→ 正式周复盘
→ AI脚手架逐步撤除
→ 独立学习与长期成果
```

## 2. 三层学习引擎

### 2.1 行为发生层

系统采用福格行为模型，将一次行为是否发生拆为：

```text
Behavior = Motivation × Ability × Prompt
```

即：动机、能力和提示需要在同一时刻汇合。

当学习行为没有发生时，系统默认采用以下顺序：

```text
先降低行为难度
→ 再修复锚点或提示
→ 最后才讨论提升动机
```

系统禁止：

- 用羞辱或人格判断解释未完成；
- 因为中断而要求补偿性加量；
- 通过断签焦虑维持使用；
- 把连续天数直接当作能力证明。

### 2.2 学习形成层

```text
目标诊断
→ 知识地图
→ 学习者先尝试
→ 最小提示
→ 主动练习
→ 误解修复
→ 间隔复习
→ 独立评估
```

系统尽量避免“AI直接给答案—用户感觉看懂—实际无法独立完成”的假掌握。

### 2.3 成果证明层

```text
阶段任务
→ 真实作品
→ 量表验收
→ 延迟复测
→ 跨场景迁移
→ 能力证据
```

微习惯只负责让正确学习行为更容易发生；是否真正掌握，必须由独立回答、延迟回忆、迁移任务、作品和证据共同证明。

## 3. CHART 生产工程模型

CHART 由五个工程维度组成：

| 维度 | 含义 | 在 Self-Study AI 中的作用 |
|---|---|---|
| C — Context | 上下文 | 当前目标的契约、会话、路径、任务、知识、资料、评估、作品和行为画像 |
| H — Harness | 执行约束 | 工具白名单、风险、审批、成本、步数、超时、文件和网络边界 |
| A — Alignment | 目标对齐 | 先尝试、反依赖、真实证据、契约优先、逐步撤除脚手架 |
| R — Runtime | 运行时 | 模型调用、数据库、学习技能、资料检索、评估、作品验收和 Checkpoint |
| T — Traceability | 可追溯性 | 原始输入、计划、工具输入输出、模型路由、成本、审批和结果 |

系统支持：

```text
A1–A5 × B1–B5 × C1–C5 × D1–D5 = 625种基础组合
```

默认正式版组合为：

```text
A5 + B5 + C5 + D5
```

## 4. 四组等级的直观理解

### 4.1 A：智能体闭环深度

| 等级 | 适合场景 | 主要结果 |
|---|---|---|
| A1 | 简单问答 | 获取信息 |
| A2 | 结构化讲解 | 建立理解 |
| A3 | 练习与反馈 | 形成迁移能力 |
| A4 | 项目和作品 | 形成可验收成果 |
| A5 | 长期自学 | 独立性、保持、迁移和长期成果 |

### 4.2 B：执行控制强度

| 等级 | 主要特点 |
|---|---|
| B1 | 不开放工具写入 |
| B2 | 以只读检索为主 |
| B3 | 允许受控执行，关键动作可审批 |
| B4 | 支持更广运行能力和风险审批 |
| B5 | 完整风险分级、预算、暂停、恢复和可逆状态 |

### 4.3 C：适应与记忆深度

| 等级 | 上下文范围 |
|---|---|
| C1 | 当前会话 |
| C2 | 当前会话及少量状态 |
| C3 | 当前目标 |
| C4 | 长期目标和更深上下文 |
| C5 | 终身学习资产、证据、误解、行为状态和持续适应 |

### 4.4 D：治理与责任链

| 等级 | 记录深度 |
|---|---|
| D1 | 最小记录 |
| D2 | 基础过程记录 |
| D3 | 标准工具与结果记录 |
| D4 | 完整 Prompt、工具和模型响应记录 |
| D5 | 完整责任链、Checkpoint、成本和验证任务双模型审计 |

## 5. 内置组合预设

| 预设 | 组合 | 推荐用途 |
|---|---|---|
| 快速导师 | A2+B2+C2+D2 | 快速解释概念 |
| 引导练习 | A3+B3+C3+D3 | 练习、纠错和迁移 |
| 项目教练 | A4+B4+C4+D4 | 项目、论文、作品和交付 |
| 终身自学 | A5+B5+C5+D5 | 长期目标、契约、微习惯、证据和周复盘 |

日常使用无需频繁修改组合。默认 A5+B5+C5+D5 已覆盖完整长期自学需求。高级用户可在当前会话的“更多 → CHART组合”中调整。

# 第二篇：安装、启动与首次配置

## 6. 运行环境

V1.0.0 的 CI 使用 Node.js 22。源码运行建议准备：

- Node.js 22；
- npm；
- Windows、macOS 或主流 Linux 桌面环境；
- 可以访问 npm 依赖源的网络；
- 至少一个模型供应商 API 密钥，或使用能力受限的本地演示模型。

项目使用 Electron 37.2.6、React 19.1.0、TypeScript 5.8.3 和 Electron Forge 7.8.1。

## 7. 从源码启动

解压源码后进入项目目录：

```bash
cd self-study-electron-v1.0.0
npm install
npm run verify
npm start
```

`npm run verify` 依次执行：

```text
源码语法与相对导入检查
→ 高置信密钥扫描
→ TypeScript严格检查
→ Vitest测试
→ ESLint
```

如果只是开发调试，也建议先运行质量检查，避免数据库迁移或模型配置问题被带入桌面运行。

## 8. 生成桌面安装包

```bash
npm run make
```

构建产物位于：

```text
out/make/
```

正式向其他用户分发前，还应完成：

- 生成并提交 `package-lock.json`；
- 使用 `npm ci` 进行可复现构建；
- Windows 代码签名；
- macOS 签名与 Notarization；
- 三平台安装与启动验收；
- 模型 API 回归测试。

## 9. 首次启动

首次启动后，界面主要由三部分组成：

```text
左侧：长期目标与独立会话
中间：当前目标聊天、唯一下一步和自然语言输入框
右侧：按需打开的结构化学习抽屉
```

首次使用建议按以下顺序完成：

1. 打开“设置”，配置至少一个模型；
2. 新建一个真实学习目标；
3. 建立该目标的一对一学习契约；
4. 设计一个 30—120 秒微习惯；
5. 编译六阶段学习路径；
6. 开始第一次专注会话；
7. 完成一个最小行动或一项练习；
8. 在适当时机完成评估和作品；
9. 一周后生成正式周复盘。

## 10. 无 API 密钥时的行为

项目包含“本地演示模型”。当云模型不可用时，系统可以回退到本地演示模型，但该模型仅用于界面和流程演示，推理、工具调用、长上下文和结构化输出能力有限。

正式学习建议至少配置一个真实模型供应商。

# 第三篇：模型与 API 配置

## 11. 打开模型设置

可以通过以下任一方式打开设置：

- 点击左侧底部设置入口；
- 使用 `Ctrl/Cmd + ,`；
- 从界面中的模型配置提示进入。

设置窗口包含：

```text
外观与阅读
模型与API
```

## 12. 内置模型供应商

V1.0.0 源码预置如下目录。模型名和端点可能被供应商调整，所有字段均可在设置页覆盖。

| 供应商 | V1.0.0 默认模型 | 协议 | 默认 Base URL | 环境变量 |
|---|---|---|---|---|
| DeepSeek | `deepseek-v4-flash` | OpenAI Chat | `https://api.deepseek.com` | `DEEPSEEK_API_KEY` |
| MiniMax | `MiniMax-M2.7` | OpenAI Chat | `https://api.minimaxi.com/v1` | `MINIMAX_API_KEY` |
| Kimi | `kimi-k3` | OpenAI Chat | `https://api.moonshot.cn/v1` | `MOONSHOT_API_KEY` |
| Qwen | `qwen-plus` | OpenAI Chat | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `DASHSCOPE_API_KEY` |
| StepFun | `step-3.7-flash` | OpenAI Chat | `https://api.stepfun.ai/v1` | `STEP_API_KEY` |
| GLM | `glm-5.2` | OpenAI Chat | `https://open.bigmodel.cn/api/paas/v4` | `ZAI_API_KEY` |
| GPT | `gpt-5.5` | OpenAI Responses | `https://api.openai.com/v1` | `OPENAI_API_KEY` |
| Gemini | `gemini-3.5-flash` | Gemini Native | `https://generativelanguage.googleapis.com/v1beta` | `GEMINI_API_KEY` |
| Claude | `claude-sonnet-5` | Anthropic Messages | `https://api.anthropic.com` | `ANTHROPIC_API_KEY` |

默认供应商为 DeepSeek。

## 13. 配置一个供应商

1. 打开“设置 → 模型与API”；
2. 在模型目录中选择供应商；
3. 检查协议、模型名称和 Base URL；
4. 输入 API 密钥；
5. 根据需要设置优先级和超时时间；
6. 点击“保存并测试”；
7. 健康检查通过后，可点击“设为默认”。

注意：

- 优先级数字越小，候选顺序越靠前；
- 默认模型会额外获得路由优先权；
- 密钥留空时，如果已经安全保存，保存其他字段不会删除密钥；
- 供应商账户使用专属区域端点时，应覆盖 Base URL；
- “测试”只验证当前配置，不代表所有复杂任务都已通过回归。

## 14. 环境变量配置

托管部署或开发环境可在启动 Electron 的 Shell 中设置：

```bash
export DEEPSEEK_API_KEY="..."
export MINIMAX_API_KEY="..."
export MOONSHOT_API_KEY="..."
export DASHSCOPE_API_KEY="..."
export STEP_API_KEY="..."
export ZAI_API_KEY="..."
export OPENAI_API_KEY="..."
export GEMINI_API_KEY="..."
export ANTHROPIC_API_KEY="..."
```

Windows PowerShell：

```powershell
$env:DEEPSEEK_API_KEY="..."
npm start
```

项目不会自动解析 `.env` 文件。`.env.example` 仅展示变量名称。

## 15. 模型路由与故障切换

系统综合考虑：

- 默认供应商；
- 用户优先级；
- 是否已配置密钥；
- 最近健康状态；
- A4/A5 对推理能力的偏好；
- C4/C5 对长上下文的偏好；
- D4/D5 对结构化输出的偏好。

故障切换顺序：

```text
默认主模型
→ 同等级候选
→ 其他已配置云模型
→ 本地演示模型
```

HTTP 408、409、425、429 和部分 5xx 会有限重试。认证错误、模型不存在和明显参数错误通常直接切换候选模型。

## 16. D5 双模型审计

当：

```text
intent = verify
且 governance = D5
```

系统会在主模型回答成功后，尝试选择另一个已配置、支持推理的非演示模型进行独立审计。

审计关注：

- 事实性；
- 逻辑性；
- 遗漏；
- 过度自信；
- 学习者依赖风险；
- 最小修正建议。

普通解释、规划或聊天不会自动触发双模型调用，避免不必要成本。

## 17. 自定义 OpenAI 兼容模型

选择“＋自定义”，配置：

- 类型；
- OpenAI Chat Completions 协议；
- 显示名称；
- 模型 ID；
- Base URL；
- API 密钥；
- 优先级；
- 超时；
- 能力标签。

Base URL 应指向供应商要求的兼容根路径，程序会追加 `/chat/completions`。

# 第四篇：界面与自然交互

## 18. 左侧目标会话栏

左侧栏用于管理长期目标。每个目标就是一个独立会话空间，包含：

- 独立聊天消息；
- 独立草稿；
- 独立学习契约；
- 独立路径和任务；
- 独立知识、误解与复习；
- 独立资料、评估、作品和证据；
- 独立微习惯、行为画像和周复盘；
- 独立 Agent Run 与审批。

支持：

- 新建；
- 搜索；
- 置顶；
- 重命名；
- 归档；
- 恢复；
- 最近打开排序。

归档不是删除。归档后全部数据继续保留。

## 19. 中央聊天区

聊天区包含：

- 当前目标名称和期望结果；
- “下一步”卡片；
- 当前目标消息；
- 模型和路由信息；
- Agent 运行状态；
- 情境建议；
- 会话内错误恢复；
- 自然语言输入框。

输入框支持：

- `Enter` 发送；
- `Shift+Enter` 换行；
- 自动增高；
- 每个目标独立草稿；
- Markdown；
- GFM 表格和任务列表；
- 行内及块级 LaTeX；
- 失败后重试。

## 20. 右侧进度抽屉

点击“进度”后，可打开以下模块：

```text
契约
目标
任务
微习惯
复习
知识
资料
评估
作品
证据
运行
```

系统默认不把所有模块堆在首页。只有需要查看结构、纠正状态或执行管理操作时，才打开进度抽屉。

## 21. 专注模式

点击“专注”或使用 `Ctrl/Cmd + Shift + F`：

- 隐藏左侧目标栏；
- 隐藏右侧进度抽屉；
- 只保留当前会话、下一步和输入框。

按 `Esc` 退出专注模式。

## 22. 会话搜索

在当前目标右上角选择“更多 → 搜索当前会话”，可只搜索当前目标的聊天记录。

目标搜索与会话搜索不同：

- `Ctrl/Cmd + K` 搜索目标名称、目标描述、结果和最近消息摘要；
- 会话内搜索只过滤当前目标消息。

## 23. 快捷键

| 快捷键 | 操作 |
|---|---|
| `Ctrl/Cmd + N` | 新建目标 |
| `Ctrl/Cmd + K` | 搜索目标 |
| `Ctrl/Cmd + ,` | 打开设置 |
| `Ctrl/Cmd + Shift + F` | 切换专注模式 |
| `Esc` | 退出专注模式或关闭进度抽屉 |
| `Enter` | 发送消息 |
| `Shift + Enter` | 换行 |

# 第五篇：快速开始——15分钟建立第一个自学系统

## 24. 第一步：创建真实目标

在新会话中直接输入：

```text
我想在12周内掌握概率论基础，能够独立解释核心概念、完成50道练习，并写一篇使用贝叶斯方法分析现实问题的报告。
```

高质量目标至少包含：

- 学什么；
- 为什么学；
- 当前基础；
- 目标水平；
- 时间范围；
- 最终作品或成果；
- 可验证的成功标准。

## 25. 第二步：建立一对一学习契约

打开“进度 → 契约”，或直接说：

```text
帮我建立一对一学习契约。我每周能投入180分钟，每次25分钟，希望你以平衡方式指导，优先要求我先尝试，最终让我能够独立解决问题。
```

确认：

- 每周时间预算真实可执行；
- 单次时长不过大；
- 成功定义可以被验证；
- 教练方式符合当前阶段；
- 自主性目标不是“永远依赖AI”。

## 26. 第三步：设计微习惯

直接说：

```text
帮我为当前目标设计一个30秒微习惯。我的稳定锚点是晚饭后打开电脑。
```

推荐配方：

```text
当我晚饭后打开电脑，
我只打开概率论目标并写下一道问题，
然后轻轻点头说“我已经开始了”。
```

最小版本完成即成功。是否继续学习十分钟由当时状态决定。

## 27. 第四步：编译学习路径

输入：

```text
为这个目标编译一条龙学习路径，按诊断、理解、知识地图、主动练习、能力验证、作品交付六个阶段安排。
```

系统会建立阶段里程碑，并逐阶段解锁。

## 28. 第五步：开始第一次会话

输入：

```text
开始一个25分钟专注学习会话，先诊断我对条件概率的真实理解。
```

结束时输入：

```text
结束本次学习会话，总结我完成了什么、哪里仍然模糊，以及下一次唯一行动。
```

## 29. 第六步：完成第一次评估

输入：

```text
考考我是否真正理解条件概率。不要只问定义，要检查机制解释、迁移和常见误解。
```

在“进度 → 评估”中一次性提交独立答案。

## 30. 第七步：一周后生成复盘

输入：

```text
生成本周正式复盘。请根据真实会话、最小行动、能力证据和作品进度，只给我下周一个重点和一个行为调整。
```

# 第六篇：目标与独立会话

## 31. 创建目标

可通过：

- 左侧“新目标”；
- `Ctrl/Cmd + N`；
- 自然语言“我想……”“我要……”“我的目标是……”创建。

创建新目标时，第一条消息、Agent Run 和后续资产会迁移到新目标的正式会话，避免混入旧目标。

## 32. 编辑目标

“进度 → 目标”支持编辑：

- 目标名称；
- 学习背景；
- 期望成果；
- 当前层级；
- 目标层级；
- 目标日期；
- 状态。

层级范围为 1—9，用于表达从开蒙、理解、应用到研究和体系建构的成长跨度。

## 33. 置顶、重命名和归档

左侧目标“···”菜单支持：

- 置顶或取消置顶；
- 就地重命名；
- 归档；
- 恢复。

重命名会同时更新目标和会话标题，防止显示名称与模型 Context 不一致。

## 34. 独立草稿

每个目标拥有自己的未发送草稿。切换目标时：

```text
保存目标A草稿
→ 打开目标B并恢复其草稿
→ 返回目标A并恢复原内容
```

草稿采用即时前端状态和约 450ms 防抖持久化。发送成功后只清空当前目标草稿。

## 35. 目标状态

| 状态 | 含义 |
|---|---|
| active | 正在推进 |
| paused | 暂停，但保留所有资产 |
| completed | 已达到目标或阶段性完成 |
| archived | 从活动列表隐藏，但可恢复 |

不要用归档代替删除敏感内容。V1.0.0 主要提供可恢复归档，而不是面向每一类对象的永久删除流程。

# 第七篇：一对一学习契约

## 36. 契约的作用

学习契约不是装饰性表单，而是当前目标的运行约束。契约决定：

- 每周最多安排多少学习时间；
- 每次会话计划多长；
- AI采用怎样的教练方式；
- 反馈是温和、直接还是证据优先；
- 当前挑战强度；
- 期望达到多少自主性；
- 何时进行正式复盘。

## 37. 契约字段

| 字段 | 建议填写方式 |
|---|---|
| 学习者名称 | 用于当前契约显示，可使用昵称 |
| 为什么现在学习 | 写清现实原因和时机 |
| 成功定义 | 必须能被作品、测试或迁移验证 |
| 每周分钟 | 按真实可支配时间填写 |
| 单次分钟 | 建议先用可持续长度 |
| 偏好日期 | 选择真正可执行的日期 |
| 偏好时间 | 可为空，也可写固定时段 |
| 教练方式 | 平衡、苏格拉底、直接、项目驱动 |
| 反馈方式 | 证据优先、温和或直接 |
| 挑战强度 | 1—5 |
| 自主性目标 | 20%—100% |
| 最低承诺 | 行为极小但明确 |
| 复盘频率 | 每周、双周或每月 |

## 38. 教练方式选择

### 平衡

适合大多数长期目标。AI会在解释、追问、练习和项目之间平衡。

### 苏格拉底追问

适合已经有基础、需要形成独立判断的学习者。AI减少直接答案，更多要求先陈述假设、证据和推理。

### 直接指导

适合零基础、时间紧或需要快速排除障碍的阶段。仍会保留反依赖边界。

### 项目驱动

适合编程、研究、写作、产品、实验等以真实作品为目标的学习。

## 39. 反馈方式选择

- **证据优先**：先指出证据、缺口和验证方式；
- **温和**：保留清晰判断，同时减少压迫感；
- **直接**：快速指出问题和下一步，不使用羞辱性语言。

## 40. 契约更新

契约采用版本化 UPSERT。修改后版本递增，当前 Context 使用最新有效契约。

以下情况建议更新契约：

- 每周时间长期无法兑现；
- 目标成果发生变化；
- 反馈方式不再适合；
- 学习者已经明显提高自主性；
- 进入项目交付或考试冲刺阶段。

# 第九篇：学习路径与里程碑

## 46. 六阶段路径

默认一条龙路径包括：

```text
起点诊断
→ 核心理解
→ 知识地图
→ 主动练习
→ 能力验证
→ 作品交付
```

每个里程碑包含：

- 目标结果；
- 必需证据；
- 预计时间；
- 顺序位置；
- 锁定、可执行、进行中或完成状态。

## 47. 编译路径

自然语言示例：

```text
为当前目标编译学习路径，每个阶段必须有证据门槛，不要只给课程列表。
```

```text
把现有路径改为项目驱动，最终作品是一份可运行的软件和技术报告。
```

重新编译会保留旧路径历史，并创建更高版本。

## 48. 完成里程碑

在“进度 → 目标”中查看当前可执行里程碑。上一阶段完成并留下所需证据后，下一阶段才解锁。

不要仅因为“看完资料”就标记完成。建议完成标准至少包含：

- 独立复述；
- 一次练习；
- 一个可检查产物；
- 或一个明确证据条目。

# 第十一篇：福格行为模型与微习惯

## 53. 行为诊断

当用户说：

```text
我最近总是没动力，为什么做不到？
```

系统进入行为诊断，而不是直接增加计划。

诊断关注：

- 动机是否不足；
- 行为是否太难；
- 锚点是否不稳定；
- 提示是否真正出现；
- 是否存在启动前准备摩擦；
- 当前最小行动是否仍然过大。

## 54. 微习惯配方

标准结构：

```text
当【稳定锚点】发生后，
我将【30—120秒最小学习行为】，
然后立即【自然庆祝】。
```

示例：

```text
当我打开当前学习目标后，
我只写下一个问题，
然后轻轻点头，对自己说“我已经开始了”。
```

## 55. 设计高质量锚点

锚点应：

- 已经稳定发生；
- 时间和场景清晰；
- 与学习行为距离近；
- 不依赖另一个尚未形成的习惯。

较好的锚点：

```text
晚饭后打开电脑
早晨坐到书桌前
打开当前项目仓库后
通勤坐下后
```

较弱的锚点：

```text
有空时
心情好时
想起来时
以后每天
```

## 56. 设计真正微小的行为

最小行为应小到不需要完整动机即可完成，例如：

- 打开目标；
- 写一个问题；
- 读一条复习卡；
- 写一行代码；
- 口头复述一个概念；
- 标记一个误解。

“学习一小时”“写完整章节”“完成整套试卷”不是微习惯。

## 57. 即时庆祝

庆祝用于强化“我已经开始”的正反馈，不要求夸张。可以是：

- 轻轻点头；
- 微笑；
- 对自己说“开始了”；
- 打一个自然的小勾；
- 深呼吸并确认完成。

## 58. Check-in结果

| 结果 | 系统解释 |
|---|---|
| 完成 | 最小版本成功，可选自然扩展 |
| 部分完成 | 行为可能仍然偏大，下一次继续缩小 |
| 跳过 | 检查能力、提示或意义连接，不责备、不补做 |

Check-in同时记录：

- 当时动机 1—5；
- 当时容易程度 1—5；
- 提示是否出现；
- 是否庆祝；
- 实际秒数；
- 备注；
- 本地日历日期；
- 时区偏移。

## 59. 频率

支持：

- 每日；
- 工作日；
- 每周指定日；
- 自定义星期组合。

工作日习惯在周一会把上一个计划日识别为上周五，不会因周末误判中断。

## 60. 暂停、恢复和退役

- **暂停**：当前不执行，但保留配方和历史；
- **恢复**：重新进入活动状态；
- **退役**：该配方不再适合当前阶段；
- **重新启用**：必要时恢复旧配方。

一个目标不宜同时启用过多微习惯。通常先保留一个最关键启动行为。

# 第十二篇：知识地图与误解修复

## 61. 知识节点

知识节点保存：

- 标题；
- 摘要；
- 学习阶段；
- 掌握度；
- 置信度；
- 前置知识；
- 相关误解。

## 62. 知识关系

支持关系：

- prerequisite：前置依赖；
- related：相关；
- contrasts：对比；
- applies-to：应用于；
- evidence-for：作为证据。

## 63. 生成知识地图

```text
为当前目标生成动态知识地图，标出前置关系、最容易混淆的概念和验证方式。
```

知识地图不是固定目录。C5 会根据练习、误解、评估和作品状态调整下一步。

## 64. 误解状态

```text
待修复
→ 验证中
→ 已解决
→ 再次出现
→ 重新修复
```

每条误解保存：

- 错误陈述；
- 正确解释；
- 所需证据；
- 状态；
- 复发次数；
- 下次检查时间；
- 解决时间。

## 65. 处理误解

推荐自然语言：

```text
我可能把独立事件和互斥事件混淆了。先不要直接告诉我，设计一个反例让我验证。
```

```text
这个误解已经解决，请安排一次延迟检查，防止复发。
```

# 第十三篇：间隔复习

## 66. 复习队列

解释、练习或验证知识后，系统可建立复习条目。每条包含：

- 提示；
- 标准答案；
- 到期时间；
- 间隔天数；
- 难度系数；
- 重复次数；
- 遗忘次数；
- 最近评分。

## 67. 四档反馈

| 评分 | 含义 |
|---|---|
| Again | 基本没有回忆出来 |
| Hard | 回忆困难或不完整 |
| Good | 能正确回忆，略有努力 |
| Easy | 快速、稳定、完整回忆 |

评分应基于真实回忆，而不是“看答案后觉得熟悉”。

## 68. 暂停与恢复

对暂时不重要、内容错误或目标已暂停的条目，可以暂停复习。暂停项目不会进入今日队列，恢复后继续调度。

## 69. 自然语言复习

```text
今天有哪些到期复习？一次只给我一道，不要先展示答案。
```

```text
我刚才只能回忆一半，把这条记为Hard，并告诉我最小纠错点。
```

# 第十四篇：本地个人资料库

## 70. 支持格式和限制

当前支持：

- TXT；
- Markdown；
- JSON；
- CSV；
- 单文件最大 5MB；
- 单次最多 20 个文件。

V1.0.0 不包含 PDF、Word、网页抓取或代码仓库 AST 解析。

## 71. 导入资料

打开“进度 → 资料 → 导入资料”，通过系统文件选择器选择文件。

安全流程：

```text
显式选择文件
→ 格式和大小检查
→ SHA-256去重
→ 文本摘要
→ 重叠分块
→ SQLite存储
→ 本地检索
```

Renderer 不能自行提交任意系统路径让主进程读取。

## 72. 搜索资料

在资料模块输入关键词。系统综合：

- 标题命中；
- 片段词组频次；
- 中文 2、3、4 字词组；
- 当前目标范围；
- 最近更新时间。

示例：

```text
从我的资料中查找“长程Agent状态恢复”，列出相关片段并区分资料事实和你的推断。
```

## 73. 来源感知回答

AI应区分：

```text
资料明确记载的事实
模型根据资料作出的推断
仍需验证的结论
建议采取的行动
```

默认不会把整个文档上传给模型，只把检索命中的必要片段加入当前一次 Context。

## 74. 归档与恢复资料

归档资料仍保留原始内容和分块，但不再进入活动检索和模型 Context。恢复后重新参与检索。

# 第十五篇：真实性能力评估

## 75. 为什么需要独立评估

聊天中的“看懂了”不能证明掌握。真实性评估要求保存学习者原始答案，并检查：

- 核心机制；
- 迁移与边界；
- 常见误解；
- 反例或验证设计。

## 76. 创建评估

```text
考考我是否真正掌握当前内容。不要只考定义，要检查机制解释、迁移和常见误解。
```

系统创建正式 Assessment，而不是普通聊天问题。

## 77. 提交答案

在“进度 → 评估”中一次性写出独立答案，然后点击“提交评估”。

回答建议包含：

1. 自己的解释；
2. 一个独立例子；
3. 一个新场景应用；
4. 一个常见误解；
5. 一个验证或反例。

## 78. 评分边界

自动评分是学习反馈，不是高风险认证。系统保存：

- 原始答案；
- 维度得分；
- 反馈；
- 是否通过；
- 生成的能力证据；
- 关联目标和意图。

模型生成内容不能直接标记为学习者独立能力。

## 79. 归档与恢复评估

- 无答题记录的评估恢复为待作答；
- 已有答题记录的评估恢复为已完成；
- 原始答案、评分和证据不丢失。

# 第十六篇：作品与能力证据

## 80. 创建作品

自然语言示例：

```text
帮我为当前目标创建一个作品：一份可运行的概率模拟程序和一篇1500字分析报告，并建立验收标准。
```

作品类型包括：

- 笔记；
- 代码；
- 文章；
- 实验；
- 项目；
- 演示文稿；
- 数据集；
- 其他。

## 81. 作品状态

```text
草稿
→ 待评审
→ 已验收
→ 归档/恢复
```

作品恢复会读取最近一次验收结果：

- 没有验收记录：恢复为草稿；
- 最近验收未通过：恢复为待评审；
- 最近验收通过：恢复为已验收。

## 82. 量表验收

```text
验收当前作品，逐项检查正确性、完整性、可复现性、独立性和是否达到契约中的成功标准。
```

验收记录与作品内容分开保存，可保留多次历史。

## 83. 能力证据

能力证据包含：

- 标题和内容；
- 类型；
- 独立性；
- 保持度；
- 迁移度；
- 评估者；
- 来源；
- 创建时间。

证据类型：

```text
explanation
exercise
project
delayed-recall
transfer
peer-review
```

## 84. 证据质量

高质量证据通常具有：

- 明确来源；
- 学习者独立完成；
- 与目标成功定义相关；
- 可复查；
- 经过延迟或迁移验证；
- 不是模型代写内容。

# 第十七篇：正式周复盘与自主性增长

## 85. 周复盘读取的数据

正式周复盘同时读取：

- 契约计划会话数；
- 实际完成会话数；
- 完成的最小行动；
- 新增能力证据；
- 用户真实反思；
- 当前自主性与目标差距。

## 86. 生成周复盘

在“进度 → 契约”填写可选反思，然后点击“生成本周复盘”，或直接说：

```text
生成本周正式复盘。依据真实记录，不要给泛泛鼓励，只给下周唯一重点和一个行为调整。
```

输出：

```text
本周事实
→ 教练判断
→ 下周唯一重点
→ 一个行为调整
```

同一周期重复生成会更新原记录，不制造重复复盘。

## 87. 自主性

系统关注学习者是否逐渐减少对 AI 的依赖。自主性不足时，系统可能：

- 先要求用户尝试；
- 降低直接答案比例；
- 使用提示阶梯；
- 增加延迟复测；
- 增加迁移任务；
- 要求作品或证据；
- 逐步撤除脚手架。

这不是拒绝帮助，而是让帮助服务于长期独立能力。

# 第十八篇：长程Agent、审批与恢复

## 88. Agent运行状态

```text
queued
→ planning
→ running
⇄ paused
→ awaiting-approval
→ completed / failed / cancelled
```

中文界面显示：准备、理解并规划、执行、暂停、等待确认、完成、失败或取消。

## 89. 暂停、继续与取消

运行状态条提供：

- 暂停；
- 继续；
- 取消。

暂停不会删除已有步骤和 Checkpoint。取消会停止后续执行，但已经持久化的学习资产仍然保留。

## 90. 风险审批

B4/B5 使用风险审批。可能需要确认的行为包括：

- 中高风险持久化写入；
- 作品或导出等重要操作；
- 超出常规边界的外部网络或文件行为。

审批前应检查：

- 目标；
- 将创建或修改的对象；
- 影响范围；
- 是否可逆；
- 成本和模型；
- 是否符合当前契约。

## 91. Checkpoint

D4/D5 默认每一步建立 Checkpoint，使长任务在异常后可恢复。Trace 保存计划、步骤、工具输入输出、模型路由、成本和最终结果。

## 92. 成本控制

默认组合中：

- A5 最大步骤为 16；
- A5 单次运行人民币预算上限为 20 元；
- A5 运行超时为 15 分钟。

实际模型费用由供应商计费决定；系统中的成本记录用于治理，不替代供应商账单。

# 第二十篇：数据、备份、恢复与导出

## 99. 数据存储

主数据库位于 Electron `userData` 目录：

```text
<userData>/self-study.db
```

备份目录：

```text
<userData>/backups/
```

日志目录：

```text
<userData>/logs/
```

具体 `userData` 路径由操作系统和 Electron 决定。

## 100. 数据库特性

- SQLite；
- Schema V10；
- WAL；
- 外键；
- 单实例锁，避免多个进程竞争写入；
- 数据迁移；
- 完整性检查。

## 101. 自动备份

系统使用 `VACUUM INTO` 创建一致性每日备份，并保留 14 份。

## 102. 手动备份

打开“进度 → 运行”，点击“立即创建备份”。

备份文件命名类似：

```text
self-study-manual-YYYYMMDDTHHMMSSZ.db
```

## 103. 恢复备份

1. 打开“运行与数据安全”；
2. 展开“查看与恢复备份”；
3. 选择备份；
4. 阅读确认提示；
5. 点击恢复；
6. 应用创建恢复前保护备份；
7. 应用重启并原子替换数据库。

恢复流程会：

- 只接受系统备份目录中的合法文件名；
- 对候选数据库执行 `PRAGMA integrity_check`；
- 删除旧 WAL/SHM；
- 失败时恢复原数据库。

## 104. 完整性检查

“运行”模块显示：

- Schema 版本；
- 数据库大小；
- 备份数量；
- 最近备份；
- 关键记录统计；
- 数据库完整性。

完整性结果不是 `ok` 时，不应继续发布、迁移或覆盖数据库。

## 105. 导出

左侧工作区操作可导出：

- JSON；
- Markdown。

导出包含：

- 目标和会话；
- 契约和周复盘；
- 路径和任务；
- 知识、误解和复习；
- 资料元数据；
- 评估和作品；
- 能力证据；
- 微习惯和 Check-in；
- Run 和学习资产。

导出不包含模型 API 密钥或 SecretStore。

# 第二十一篇：安全与隐私

## 106. Electron安全边界

正式版启用：

```text
contextIsolation: true
sandbox: true
nodeIntegration: false
webSecurity: true
```

- Renderer 不直接访问数据库和文件系统；
- Preload 只暴露类型化白名单 API；
- IPC 写操作使用 Zod；
- 权限请求默认拒绝；
- WebView 被禁止；
- 新窗口被拒绝，HTTPS链接交给系统浏览器。

## 107. API密钥

- 使用 Electron `safeStorage` 加密；
- 或由环境变量注入；
- Renderer 无法读取；
- Trace、日志、导出和 Markdown 不保存密钥；
- 系统无法安全加密时拒绝明文降级；
- 不应把密钥写入源码、截图、Issue或日志。

## 108. 日志

日志使用 JSON Lines，位于 `<userData>/logs`：

- 5MB 轮转；
- 最多 5 份归档；
- API Key、Authorization、Secret、Token、Password 自动脱敏；
- 记录主进程异常、Renderer 崩溃或卡死、启动和退出。

## 109. 学习与行为数据

动机、能力、提示、微习惯和 Check-in：

- 默认保存在本地 SQLite；
- 只进入当前目标的最小必要 Context；
- 不应用于广告、人格标签、惩罚或跨目标推断；
- 不自动升级为能力证据。

## 110. 资料和消息安全

- 导入必须显式授权；
- 只支持白名单文本格式；
- 不执行脚本、HTML或命令；
- Markdown不执行原始HTML；
- 代码块复制不会获得命令执行权限；
- 外部链接由主进程决定是否交给浏览器。

## 111. V0.9升级到V1.0

首次打开旧 V0.9 数据库时，系统升级到 Schema V10，新增：

```text
learning_contracts
weekly_learning_reviews
```

旧数据保持：

- 目标；
- 会话和消息；
- 草稿；

- 资料、评估、作品、证据；
- 微习惯和 Check-in；
- 模型配置；
- Run、Trace 和 Checkpoint。

系统不会自动为旧目标制造未经用户确认的契约。

## 112. 升级前操作

1. 在旧版本中创建手动备份；
2. 导出 JSON 和 Markdown；
3. 关闭应用；
4. 备份整个 `userData` 目录；
5. 升级应用；
6. 首次启动后检查 Schema 和完整性；
7. 抽查旧目标、消息和关键作品。

- 数据迁移破坏旧目标或消息；
- API 密钥进入 Renderer、日志或导出；
- 数据库完整性不是 `ok`；
- 高风险写入绕过 Harness 或审批；
- 未生成锁文件；
- 类型检查、测试或 Lint 失败；
- 安装包未签名或来源未声明。

# 第二十四篇：故障排查

## 119. 应用无法从源码启动

检查：

1. Node.js 是否为 22；
2. `npm install` 是否完整；
3. 是否存在依赖代理 404 或 503；
4. 是否运行 `npm run verify`；
5. 是否有旧的半成品 `node_modules`；
6. Electron Forge 是否安装成功。

可尝试：

```bash
rm -rf node_modules
npm install
npm run verify
npm start
```

Windows 请使用等价的目录删除方式。

## 120. 模型测试失败

依次检查：

- API 密钥是否正确；
- 模型 ID 是否存在；
- Base URL 是否属于当前账户或区域；
- 协议是否正确；
- 账户是否有余额和权限；
- 网络是否可访问供应商；
- 超时时间是否过短；
- 是否被速率限制。

认证或模型不存在错误不应反复重试，应先修正配置。

## 121. 回答使用了本地演示模型

可能原因：

- 云模型未配置密钥；
- 供应商健康检查失败；
- 所有云候选请求失败；
- 主模型被停用；
- 当前模型配置错误。

打开设置检查启用状态、默认供应商和测试结果。

## 122. 目标数据看起来混在一起

正常情况下每个目标严格隔离。检查：

- 当前左侧是否选中了正确目标；
- 是否在新目标创建完成前误切换；
- 是否查看了工作区导出而非当前目标模块；
- 数据库是否从旧版本异常迁移。

先创建备份，再检查 Schema 和完整性。不要直接编辑 SQLite 文件。

## 123. 草稿没有恢复

- 确认草稿属于哪个目标；
- 切回原目标；
- 等待约 450ms 持久化后再退出；
- 检查数据库是否可写；
- 检查是否发送成功，发送后当前草稿会被清空。

## 124. Markdown或公式显示异常

检查：

- 公式是否使用成对 `$` 或 `$$`；
- 反斜杠是否正确；
- 代码块是否闭合；
- 是否使用不受信任的 KaTeX 命令；
- 原始 HTML 会被忽略，这是安全设计。

## 125. 无法导入文件

确认：

- 文件为 TXT、MD、Markdown、JSON或CSV；
- 单文件不超过5MB；
- 单次不超过20个；
- 文件可读取；
- 相同内容是否已经通过 SHA-256 去重导入。

## 126. 复习没有出现

检查：

- 条目是否到期；
- 是否被暂停；
- 当前是否选中了正确目标；
- 是否已经完成过解释、练习或验证并创建复习条目。

## 127. 微习惯连续性异常

系统按本地日历日期和当次时区偏移计算。检查：

- 频率是每日、工作日、每周还是自定义；
- 设备时区是否在 Check-in 期间变化；
- 是否记录为完成、部分完成或跳过；
- 连续天数仅用于观察，不影响能力证据。

## 128. 数据库恢复失败

- 不要手工移动恢复标记；
- 备份必须位于固定 backups 目录；
- 文件名必须符合系统规则；
- 候选数据库完整性必须为 `ok`；
- 确保磁盘空间充足；
- 检查日志目录中的主进程错误。

# 第二十五篇：常见问题

## 129. Self-Study AI会替我完成学习吗？

不会。A3—A5 默认要求学习者先尝试，A4—A5 要求证据。系统设计目标是提高独立性，而不是形成长期代做依赖。

## 130. 微习惯完成是否代表掌握？

不代表。微习惯只证明正确行为更容易发生。掌握必须由评估、延迟回忆、迁移和作品证明。

## 131. 可以同时管理多个目标吗？

可以。每个目标拥有独立会话和资产。为了减少认知切换，建议只置顶少量当前主线目标。

## 132. 可以离线使用吗？

本地数据库、目标管理、资料检索和演示模型可离线；真实云模型调用需要网络。当前资料库检索不依赖第三方向量服务。

## 133. 是否支持PDF和Word资料？

V1.0.0 当前不支持。只支持 TXT、Markdown、JSON和CSV。

## 134. API密钥是否会导出？

不会。密钥存储在 Electron `safeStorage` 或环境变量中，不进入 JSON/Markdown 学习资产导出。

## 135. 为什么系统总让我先尝试？

因为 A3—A5 的 Alignment 要求学习者先尝试，并通过最小提示逐步形成独立能力。可在契约中选择更直接的教练方式，但不会取消反依赖原则。

## 136. 为什么下一步总是很小？

当动机、能力或提示不稳定时，系统优先降低行为难度。小行动负责启动，不代表最终学习目标很小。

## 137. 是否可以修改CHART等级？

可以。从当前会话“更多 → CHART组合”调整。非工程用户建议使用预设，不要为了“更强”盲目把所有等级拉满。

## 138. D5是否会增加成本？

验证意图可能触发第二模型审计，因此可能增加模型调用成本。普通聊天不会无条件双模型调用。

## 139. 如何证明我真的进步了？

查看“证据”模块，并优先关注：

- 独立完成；
- 延迟保持；
- 新场景迁移；
- 作品验收；
- AI提示逐步减少。

## 140. 如何停止一个目标？

可以暂停、完成或归档。归档可恢复，不等于永久删除。

# 结语

Self-Study AI V1.0.0 的核心不是让 AI 说得更多，而是帮助学习者形成以下长期循环：

```text
更容易开始
→ 更主动练习
→ 更准确发现误解
→ 更可靠延迟保持
→ 更真实跨场景迁移
→ 更独立完成作品
→ 更少依赖AI
```

每次使用时，只需要回到三个问题：

1. 当前真实目标是什么？
2. 今天最小但有效的下一步是什么？
3. 哪条证据能证明能力真的增长了？

当目标、行为和证据能够持续对齐，Self-Study AI 才真正成为长期自学操作系统，而不是另一个短期问答工具。
